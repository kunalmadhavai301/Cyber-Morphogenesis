Interactive ML-KEM Key Encapsulation

A simple step-by-step walkthrough showing how Alice (Recipient) and Bob (Sender) establish a quantum-safe shared secret.

How This Demonstration Works (in 30 seconds)
1. Alice Generates Keys Alice creates a Public Key (which she can share with the world) and keeps a Private Key safe in memory.
2. Bob Encapsulates Bob uses Alice's public key to create a 32-byte secret code, locks it into a Ciphertext, and sends it to Alice.
3. Alice Decapsulates Alice uses her private key to unlock the ciphertext and retrieve the exact same 32-byte secret code.
4. Constant-Time Match Both check if their secrets match. If an attacker tampers with the ciphertext, ML-KEM silently gives a fake key!

What happens if a hacker corrupts the ciphertext? Under FIPS 203 §5.3, ML-KEM doesn't crash or throw an error. It quietly derives a fake random key so attackers can't learn anything!

Security Guarantee
  • Private keys and shared secrets are never sent over HTTP JSON or printed in logs.
  • Secrets are compared inside server RAM using constant-time algorithms.
